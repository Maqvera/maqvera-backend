# Public B2C Booking Site API

PRD "CRM Feature Map by Phase" Phase 2 module 15. All routes live under `routes/PublicBookingRoutes.js`, mounted at `/api/v1/public`, and are deliberately the one router in this codebase reachable **without** `authenticateAccessToken` on any endpoint — every other public-reachable surface (Stripe OAuth callback, webhook receivers) is a single narrow endpoint elsewhere, not a whole router. Tenant identity is never taken from a JWT here (there isn't one); it's resolved from a `tenantSlug` an agency opts into publishing via `TenantProfileModel.publicSlug` (see below). Every downstream query is still filtered by the tenantId that resolves to — same "tenant is the only isolation boundary" discipline as the rest of this codebase, just entered through a different door. Rate-limited more tightly than any authenticated route (`routes/PublicBookingRoutes.js`'s own `browseLimiter`/`writeLimiter`) since this is genuinely open to anonymous traffic.

## Publishing a tenant's public site

- `PUT /api/v1/tenant-profile` (existing endpoint, `controllers/TenantProfileController.js`) now also accepts `publicSlug` — lowercase letters/numbers/hyphens only, globally unique across tenants. A tenant with `publicSlug: null` (the default) has no public site at all; every `/public/*` lookup for a slug that doesn't resolve, or a tenant whose `TenantModel.status` isn't `"active"`, 404s/400s rather than leaking any data.
- `PATCH /api/v1/packages/package-templates/{templateId}` (existing template resource, new fields) — `{name?, description?, active?, publicVisible?, packageType?, images?, displayPriceFrom?, displayCurrency?}`. A `PackageTemplateModel` (created via the existing `POST /packages/{packageId}/save-as-template`) stays internal-only until a staff member sets `publicVisible: true` here — rejected with a 400 unless `displayPriceFrom` is also set (the template's own `sellingCurrency`, set when it was saved, is required too). `displayPriceFrom` is an admin-set **marketing** price ("starting from"), never a live calculation — an anonymous visitor browsing has no travel dates yet for the pricing engine to price against.

## Browsing (public, no auth)

- `GET /api/v1/public/packages?tenantSlug=...&type=&minPrice=&maxPrice=&duration=&page=&pageSize=` — paginated list of `publicVisible: true`, `active: true` templates for the tenant `tenantSlug` resolves to. `type` matches `packageType` exactly; `minPrice`/`maxPrice` filter on `displayPriceFrom`; `duration` filters on nights computed from the template's own segments (`max(offsetDays + nights)`), never a separately-stored, possibly-stale field. Returns `{ agency: {companyName, logoUrl, primaryColor, secondaryColor}, items: [...], pagination }`.
- `GET /api/v1/public/packages/{id}?tenantSlug=...` — detail view of one template (segments' city/country/mealPlan/offsetDays/nights, no hotelCatalogId or any other internal reference). 404s if the template isn't `publicVisible` for that tenant, same as a nonexistent id — a public caller can never distinguish "doesn't exist" from "not published."

## Writing (public, no auth, tightly rate-limited)

- `POST /api/v1/public/leads` — `{tenantSlug, firstName, lastName?, email?, phone?, notes?}`. Thin wrapper around the existing `LeadService.createLead` (`source: "Website"` always) — no new lead logic, just a public entry point.
- `POST /api/v1/public/bookings` — `{tenantSlug, packageTemplateId, travelStartDate, travelers?: {adults, children, infants}, roomTypeId?, customer: {firstName, lastName, email, phone}}`. Deliberately a thin orchestration over three already-existing `PackagePricingService` methods, never a second/parallel pricing or booking-creation path:
  1. **Find-or-create the customer** — looked up by `tenantId` + email first (case-insensitive) so a repeat visitor is never turned into a second `CustomerModel` row; otherwise created via the real `CreateCustomer` controller function (same `fakeReq`/`fakeRes` reuse pattern `LeadService.convertToCustomer` already uses), so a public visitor gets the exact same side effects (timeline, preferences, audit log) a staff-created customer does. A fuzzy-duplicate match from `CreateCustomer`'s own duplicate detection is resolved to the existing customer rather than surfaced as an error.
  2. **`PackagePricingService.cloneFromTemplate`** — clones the template into a real `PackageModel` for the visitor's real `travelStartDate`/`travelers`.
  3. **`PackagePricingService.calculatePackage`** — prices it for real, against real current hotel/transport/flight/visa rates. If it isn't `ready` (a rate is missing/expired/on-request for these dates), the request 400s with "This package cannot be priced for the selected dates right now — please contact the agency directly" rather than creating an unbookable booking.
  4. **`PackagePricingService.convertPackageToBooking`** — a client-supplied `roomTypeId` is only honoured if it's actually a row in the just-calculated matrix (a stale/guessed id from a cached page can never silently price the wrong room); otherwise the cheapest available room is selected automatically. Creates a real `BookingHeaderModel` in the system's normal default (`draft`) status.
  5. **Best-effort checkout** — `PaymentGatewayService.createCheckoutSession` is attempted for the booking's outstanding balance; failure (no Stripe account connected yet, zero balance) never fails the booking itself. Response always includes a `checkout` object: `{available: true, url, sessionId}` or `{available: false, reason}`.

  Response: `{bookingId, bookingNumber, customerId, selectedRoomType: {roomTypeId, roomTypeName, finalPricePerPerson}, checkout}`.
